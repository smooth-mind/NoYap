# Security Policy

## Supported version

NoYap is currently pre-1.0. Security fixes target the latest release.

## Reporting a vulnerability

Do not disclose sensitive vulnerability details in a public GitHub issue.

Report NoYap vulnerabilities privately by emailing:

`madmax37571@gmail.com`

Include, when available:

- the affected NoYap version;
- a description of the vulnerability;
- reproduction steps;
- the potential impact;
- any suggested remediation.

The maintainer will acknowledge the report and coordinate responsible
disclosure after the issue has been assessed.

## Projects created with NoYap

Projects created from NoYap must replace this contact with their own private
security-reporting method before public release.

## Scope

NoYap is primarily a governance template and local validation script. It does not make generated applications secure by itself. Each project must define and review its own security model, dependencies, data handling, secrets, deployment, and threat boundaries.

Never place credentials, private keys, production data, or confidential documents in NoYap Markdown files.
